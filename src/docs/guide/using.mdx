# Как пользоваться

Всё, что нужно, чтобы собирать экраны: как кит думает, какие у него переключатели, как устроены формы, лента,
всплывающие слои, TUI, «сигнал», эффекты, звук и строки. Каждый раздел заканчивается ссылкой на страницу
компонента — там все состояния и таблица пропсов.

## Пять правил, на которых держится всё остальное

1. **Экран — композиция примитивов.** Кит не знает про каналы, сервер и сторы: строка сообщения умеет раскладку
   и состояния, а не загрузку. Понадобился стор или транспорт — это слой `features/*` приложения, а не кит.
2. **Цвет, размер и отступ — только токены.** `var(--text-muted)`, `var(--space-3)`, `var(--control-md)`. Ни одного
   hex в модулях: тема, акцент пространства и стиль «сигнал» меняют токены, а не компоненты.
3. **Режимы — атрибутами, а не пропсами.** Тема, эффекты, TUI, стиль, звук ставятся атрибутом `data-*` на `<html>`
   или на любом контейнере. Компонент не принимает «тёмную тему» пропсом и не знает, где находится.
4. **Ни одной строки в разметке.** Все подписи кита — из словаря (`useUiStrings`), язык — у
   `UiStringsProvider`. Свою подпись экран передаёт пропсом (`label`, `placeholder`), и она главнее словаря.
5. **Доступность встроена, но не бесплатна.** Фокус, клавиатура, роли и подписи у кита есть; осмысленные
   подписи кнопок-иконок, заголовки страниц и порядок фокуса между блоками — забота экрана.

## Переключатели-атрибуты

| Атрибут              | Значения                               | По умолчанию | Чем ставить                                        |
| -------------------- | -------------------------------------- | ------------ | -------------------------------------------------- |
| `data-theme`         | `dark` / `light`                       | `dark`       | `initTheme()`, `useTheme().setTheme`, `ThemeScope` |
| `data-effects`       | `off` / `subtle` / `rich`              | `subtle`     | `initEffects()`, `useTheme().setEffects`           |
| `data-tui`           | `off` — убрать TUI-знаки               | включено     | атрибут на контейнере                              |
| `data-style`         | `signal`                               | нет          | `SignalScope`, нужен `@haunt/ui/signal`            |
| `data-signal-font`   | одно из десяти имён `signalFonts`      | Archivo      | `SignalScope font`                                 |
| `data-signal-accent` | `lime` / `magenta` / `cyan` / `orange` | `lime`       | `SignalScope accent`                               |
| `data-sound`         | `off` / `subtle` / `on`                | `off`        | `sound.setLevel()`                                 |
| `data-fx-renderer`   | `webgl` / `canvas2d` / `static`        | сам выбирает | принудительно — для отладки и слабых машин         |

Атрибут действует на свой контейнер и всё внутри. Ближайший выигрывает: `ThemeScope theme="light"` внутри тёмного
приложения светлый, а его всплывающие слои — тоже, потому что порталы кита наследуют переменные скоупа.

## Тема, уровень эффектов и акцент

<ThemeControls />

```tsx
import { useTheme } from '@haunt/ui';

function Settings() {
  const { theme, toggleTheme, effects, setEffects } = useTheme();
  // setTheme и setEffects пишут атрибут на <html> и сохраняют выбор в localStorage
}
```

**Акцент пространства** — три цвета (`--accent`, `--accent-2`, `--accent-contrast`) на контейнере. Всё
остальное (`--accent-text`, `--accent-soft`, свечение, градиенты) выводится из них на каждом элементе, поэтому
внутри `AccentScope` меняется сразу всё: кнопки, аура рейла, ссылки, выделение.

<AccentDemo />

```tsx
<AccentScope accent="teal">{/* экран сообщества */}</AccentScope>
// или свой: <AccentScope accent={{ accent: '#2bb3a0', accent2: '#1d8fb0', contrast: '#ffffff' }}>
```

Пресеты — `accentPresets`: violet, indigo, teal, lime, amber, rose, sky. Белый текст на `accent` у каждого даёт
контраст ≥ 4.5 — свой цвет стоит проверить так же.

**Токены из кода** — типизированно: `tokens.textMuted` → `'var(--text-muted)'` для инлайн-стиля,
`setTokens(element, { radiusLg: '4px' })` с откатом, `<TokenScope tokens={…}>` на часть экрана (всплывающее
внутри тоже получает значения), `readToken(key, element)` — вычисленное значение для canvas и графиков.
Опечатка в имени — ошибка компиляции. Подробно — [Токены](?path=/docs/токены--docs#токены-в-коде).

## Раскладка

- **`Stack` и `Inline`** — колонка и строка. `gap` — шаг шкалы отступов (`gap={2}` = 8 px, есть полушаги
  `gap={1.5}`), `align`, `justify`, `wrap`, `grow`. **`Box`** — отступы `p`, `px`, `py`… и `radius` без своей раскладки.
  **`Grid`** — колонки.
- **`Surface`** — слой с заливкой. `level={1|2|3}` — глубина (рейл → сайдбар → контент), `panel` — почти
  непрозрачный слой приложения с зерном и прожектором, `glass` — только для плавающего, `floating` — с тенью,
  `interactive` — карточка-кнопка.
- **`AppShell`** — оболочка приложения. Острова (`variant="islands"`, по умолчанию) — панели отдельными блоками
  с зазором, где виден живой фон; `flush` — встык. Пример — на странице
  [AppShell](?path=/docs/раскладка-appshell--docs).
- **Прокрутка.** `ScrollArea` для обычной области (`grow` — занять остаток колонки), `VirtualList` — для тысяч
  строк и ленты чата (своя область прокрутки, внутрь `ScrollArea` не кладётся).
- **Переполнение.** `Text truncate` — одна строка с многоточием (родителю нужен `min-width: 0`), `Text wrap` —
  переносить длинные ссылки в сообщениях. У `NavItem`, `Chip` и меню обрезание встроено.

## Текст

- `Text` — основной текст: `size`, `weight`, `tone` (`default`, `muted`, `subtle`…), `mono`, `as`.
- `Heading` — заголовки `level` 1–6 и `size`; `marker` — TUI-знак `>` перед разделом, `overline` — моно-капитель
  категории (как подписи групп в сайдбаре).
- `Markdown` — сообщения и описания: ссылки, упоминания, спойлеры `||…||`, код; рендер грузится лениво.
  `inline` — одна строка без блоков (био профиля).
- `Timestamp` — время с одним таймером на страницу: `relative`, `time`, точное время — в подсказке.

## Формы

<FieldDemo />

```tsx
<Field
  label="Имя пространства"
  hint="Его видят все участники"
  error={error}
  count={name.length}
  maxLength={32}
>
  <Input value={name} onChange={(event) => setName(event.target.value)} invalid={Boolean(error)} />
</Field>
```

- **`Field`** связывает метку, подсказку и ошибку с контролом внутри сам: `id`, `aria-describedby`,
  `aria-invalid` ставить руками не нужно. `optional` — пометка `[опц.]`, `aside` — ссылка справа от метки,
  `count` + `maxLength` — счётчик.
- **Соглашение API.** Составные контролы — `value` / `defaultValue` / `onValueChange` (`Select`, `Combobox`,
  `TagInput`, `Slider`, `DatePicker`…). Нативные поля (`Input`, `Textarea`) — как в HTML: `value` / `onChange`.
  Ошибка — `invalid`, размер — `size="sm" | "md" | "lg"` (24 / 28 / 32 px, кнопка того же размера — той же
  высоты), растянуть — `fullWidth`, класс на рамку — `wrapperClassName`.
- **Ритм.** Между полями формы — `Stack gap={4}`: поле читается одним блоком, поля — отдельными.
- **Файлы** — `FileDropzone` в форме и `FileDropOverlay` на экране: пока над окном тянут файлы, весь экран
  становится зоной броска («Загрузить в #общий»). Один слой на экран; встроенная зона рядом принимает бросок сама.
- Кнопка отправки — `Button loading` на время запроса, ошибка формы целиком — `Callout tone="danger"` над ней.

## Всплывающие слои

- **Порталы — сами.** `Dialog`, `Popover`, меню, подсказки, `Select` берут контейнер из `usePortalContainer()`:
  внутри `AccentScope` / `ThemeScope` слой получает их переменные. Проп `container` вручную не нужен.
- **Фокус** уходит внутрь слоя и возвращается на триггер. Слой без триггера (палитра по сочетанию, диалог из
  пункта меню) возвращает фокус через `lib/use-return-focus.ts`.
- **`Dialog.Content` без описания** — `aria-describedby={undefined}`, иначе Radix предупреждает в консоли.
- **Уведомления** — `toast.success('Сохранено')`, `toast.error('Ошибка', { description })`, `toast.show(…)`.
  Звать можно откуда угодно, `Toaster` один на приложение. Не больше четырёх сразу, F8 — фокус на тосты.
- **`HoverCard`** открывается только мышью (так устроен Radix): то же содержимое должно открываться и кликом.
  `ProfileHoverCard` это уже делает: по умолчанию (`trigger="both"`) — наведением, кликом, тапом и с клавиатуры.

## Лента сообщений

<FeedDemo />

```tsx
const grouped = groupMessages(messages, { author: (m) => m.authorId, time: (m) => m.createdAt });

messages.map((message, i) => (
  <MessageItem
    key={message.id}
    author={message.authorName}
    authorColor={message.roleColor}
    avatar={<Avatar name={message.authorName} size="lg" shape="rounded" />}
    timestamp={message.createdAt}
    grouped={grouped[i]}        // продолжение: без аватара, след автора в колонке
    groupEnd={!grouped[i + 1]}  // последнее в группе: отступ снизу
    reply={message.reply && <ReplyPreview author={…} text={…} onJump={…} />}
    actions={<MessageActions />}
  >
    <Markdown>{message.text}</Markdown>
  </MessageItem>
));
```

- **Группа** — сообщения одного автора ближе пяти минут в один день: шапка и аватар у первого, у остальных —
  след автора (линия его цвета). Окно и свои причины разрыва — опции `window` и `breakBefore` у `groupMessages`.
- **Разделители** — `DateDivider` (день, «сегодня», «вчера») и `UnreadDivider count` (`[ 2 новых ]`).
- **Состояния строки** — `mentioned`, `highlighted`, `editing`, `pending`, `failed` + `onRetry`, `edited`,
  `deleted`; `compact` — плотная лента без аватаров.
- **Длинная лента** — `VirtualList` в режиме чата: прилипает к низу, держит позицию при подгрузке старых.
  `JumpToLatest` — кнопка «к последним», когда пользователь листает историю.

## TUI-словарь

TUI — приправа, а не стиль: моно у служебного, знаки с одним значением у каждого.

| Знак    | Значит                                | Где                                                               |
| ------- | ------------------------------------- | ----------------------------------------------------------------- |
| `>`     | раздел, «вы здесь»; приглашение ввода | `Heading marker`; `Input prompt`, `CommandLine`, поиск `Combobox` |
| `[ … ]` | метка, свойство                       | `Badge bracket`, роли в `ProfileCard`, `UnreadDivider`            |
| `//`    | комментарий, пояснение                | подсказка `Field`, разделы `ProfileCard`                          |
| `!`     | ошибка                                | ошибка `Field`, `TagInput`                                        |
| `│`     | разделитель пунктов строки            | `StatusBar`                                                       |
| `/`     | разделитель пути                      | `Breadcrumbs`                                                     |

Компоненты раздела **TUI** (`LogView`, `CommandLine`, `Pager`, `TuiTable`, `BoxFrame`, `Powerline`,
`TuiProgress`, `TuiSpinner`) — терминал по правилам: настоящие знаки псевдографики из шрифта глифов кита,
сетка `ch` × `--tui-leading`, фокус курсором и инверсией. `data-tui="off"` превращает их в обычные
компоненты кита, а знаки словаря гасит.

## Стиль «сигнал»

Технический язык поверх основы: кислотный акцент, прямые углы, срезы, засечки, капитель, дисплейные заголовки.

```tsx
import '@haunt/ui/signal'; // на экране, где стиль нужен

<SignalScope font="tektur" accent="lime">
  {/* … */}
</SignalScope>;
```

Без атрибута стиль не меняет ни одного пикселя. Компоненты раздела **Сигнал** (`ChamferPanel`, `CornerFrame`,
`DataPlate`, `Barcode`…) работают и в основном стиле — нейтрально. Подробно — страница
[Стиль «сигнал»](?path=/docs/стиль-сигнал--docs).

## Эффекты и движение

- **Уровни.** `off` гасит украшения (свечение, частицы, каскады, появление при прокрутке), `subtle` —
  по умолчанию, `rich` — ярче. `prefers-reduced-motion` гасит всё, что движется, кроме индикаторов
  (`data-motion-keep`: спиннер, каретка, бегущий блок прогресса).
- **Смена состояния** (переезд индикатора, перестановка списка, появление слоя) при `off` остаётся и гаснет только
  при reduced-motion: без неё не видно, что куда делось.
- **В своём коде** спрашивайте `isMotionAllowed()` (украшение) или `prefersReducedMotion()` (смена состояния)
  из `@haunt/ui/fx`, а не читайте атрибуты сами.
- **Движение без Motion** — `Presence` (появление и уход слоя), `useFlipList`, `spring()`, `Stagger`,
  `ScrollReveal`, `startViewTransition`. Motion с пресетами — только экранам, которые его подключили
  (`@haunt/ui/motion`).
- Живой фон реагирует на события: `ambient.pulse(x, y)` или `ambient.pulseFrom(element)` — например, на отправку
  сообщения; `ambient.jump()` — переход между пространствами.

Карта эффектов и что их выключает — [Движение и эффекты](?path=/docs/движение-и-эффекты--docs).

## Звук

```tsx
import { sound, useSound, SoundSlot } from '@haunt/ui/sound';

sound.setLevel('subtle'); // уровень на <html>; без него звук выключен
sound.play('send'); // из любого места

const play = useSound(ref); // в компоненте: уровень — с ближайшего [data-sound]
<SoundSlot press="send">
  <Button>Отправить</Button>
</SoundSlot>; // озвучить чужой компонент
```

Восемь звуков (`click`, `hover`, `send`, `mention`, `voice-join`, `voice-leave`, `error`, `success`) синтезируются
на Web Audio, файлов нет. На `subtle` звучат только значимые (щелчки и наведение молчат). `AudioContext`
создаётся после первого жеста пользователя — так требует браузер. Кит сам ничего не озвучивает: что звучит,
решает экран.

## Строки и язык

- Приоритет: проп компонента (`label`, `placeholder`…) > `strings` у провайдера > словарь языка.
- Свой язык — `<UiStringsProvider locale="de" strings={deStrings}>`; языки без словаря получают английский.
- Числа — через `plural` (`Intl.PluralRules`): «1 вложение», «3 вложения», «5 вложений».
- Время и даты форматирует Intl по локали провайдера; у компонента можно перебить пропом `locale`.

## Доступность: что даёт кит, что — экран

| Кит                                                       | Экран                                            |
| --------------------------------------------------------- | ------------------------------------------------ |
| роли, `aria-*`, связь метки и поля                        | понятные подписи `IconButton label` и полей      |
| клавиатура: стрелки в меню, списках, рейле, доке, ленте   | порядок фокуса между блоками страницы            |
| видимый фокус (`:focus-visible`), возврат фокуса со слоёв | заголовок страницы и `<h1>`                      |
| reduced-motion и `data-effects`                           | не прятать смысл только в цвете своего контента  |
| контраст токенов ≥ AA в обеих темах и в «сигнале»         | проверять свои цвета (акцент пространства, роли) |

Нарушения видны на панели **Accessibility** у каждой истории.
