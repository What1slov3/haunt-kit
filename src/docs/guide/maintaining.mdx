# Как поддерживать

Как держать кит здоровым: какие проверки есть и что каждая ловит, как разбирать нестабильные тесты, как
обновлять зависимости, следить за весом, смотреть на результат глазами и где записаны решения.

> В репозитории нет git-хука и CI: ни одна проверка не запустится сама. `pnpm verify:js` перед коммитом —
> единственная сетка безопасности, и её держит человек.

## Карта проверок

| Команда                                   | Что проверяет                                                         | Когда                                        |
| ----------------------------------------- | --------------------------------------------------------------------- | -------------------------------------------- |
| `pnpm verify:js` (корень)                 | eslint без предупреждений, prettier, `tsc -b` всех пакетов, все тесты | перед каждым коммитом                        |
| `pnpm --filter @haunt/ui test:unit`       | чистая логика в jsdom: модели, строки, шрифт глифов, звук             | во время работы, быстро                      |
| `pnpm --filter @haunt/ui test:watch`      | то же в режиме наблюдения                                             | пока пишете логику                           |
| `pnpm --filter @haunt/ui test:stories`    | каждая история в Chromium: рендер и `play`                            | после правок разметки и поведения            |
| `pnpm --filter @haunt/web test:e2e`       | Playwright против витрины `/ui`: тема, эффекты, мессенджер, фильтры   | после правок примитивов; не входит в verify  |
| `pnpm build:web`                          | сборка приложения: типы и размеры чанков                              | после правок импортов и тяжёлых зависимостей |
| `pnpm --filter @haunt/ui build-storybook` | статическая сборка каталога                                           | перед выкладкой каталога                     |

`pnpm verify` из корня — то же плюс Rust (`cargo fmt`, `clippy`, `cargo test`).

## Что ловит каждый вид тестов

- **Юнит в jsdom** (`src/**/*.test.ts`, `scripts/**/*.test.ts`) — функции без DOM: группировка сообщений,
  раскладка таблиц и оболочки, математика дока и жестов, огибающие и лимитер звука, форматы времени.
  Здесь же **сторож строк** (`strings/no-hardcoded-strings.test.ts`: кириллица в строке компонента — ошибка) и
  **тест шрифта глифов** (`scripts/tui-font.test.ts`: файл в репозитории совпадает с генератором, покрытие
  диапазонов, стыки линий) и **тест токенов** (`scripts/tokens.test.ts`: `theme/tokens.generated.ts` собран из текущего CSS).
- **Истории в Chromium** — всё, что нужно настоящему браузеру: Radix, фокус, клавиатура, порталы, анимации
  появления, раскладка. Падение показывает ссылку на историю: панель **Interactions** проигрывает `play` по шагам.
- **Доступность** — axe на каждой истории, панель **Accessibility**. Режим `a11y: { test: 'todo' }`: нарушения
  видны в панели и в выводе, но прогон не валят — правило ужесточить, когда нарушения будут разобраны.
- **e2e** — сквозные сценарии витрины на живом dev-сервере (Playwright поднимает его сам).

## Нестабильные истории

Под полным прогоном (сотни историй параллельно) отдельные истории иногда падают и проходят в одиночку. Так
вели себя `VirtualList → load-older`, `ConfirmDialog → from-menu`, `DataTable → virtual-5000`,
`ImageLightbox → двойной клик и перетаскивание`, `Toast → закрытие крестиком`; у `Tour` первую карточку
истории теперь ждут дольше (`firstCard`).

1. Прогнать файл отдельно: `pnpm --filter @haunt/ui test:stories src/<компонент>`.
2. Проходит в одиночку — это гонка под нагрузкой, а не поломка. Чинить ожиданием, а не паузой:
   `await waitFor(() => expect(…))`, `findBy…` вместо `getBy…`, `expectVisible` / `expectGone` из
   `lib/stories/play-helpers.ts`.
3. Падает и в одиночку — настоящая регрессия: разбирать по шагам на панели **Interactions**.
4. Не отключать историю и не добавлять `sleep`: тест, который молчит, хуже упавшего.

## Заморозка

Кит заморожен с 2026-10-27 (`docs/decisions/0013-ui-kit-freeze.md`), с версии 1.0.0 — повторно
(`docs/decisions/0014-ui-kit-1-0.md`, что вошло — `CHANGELOG.md`). Что это значит на практике:

- **Можно всегда:** исправить ошибку, довести вид до правил (токены, «сигнал», TUI), улучшить доступность,
  дописать историю или документацию, убрать узнаваемую чужую деталь (`docs/ui-kit.md`, 10c).
- **Только по требованию экрана:** новый компонент, новый проп, новый вариант. В описании изменения — какой экран
  этого требует.
- **Смена API** (переименование, удаление пропа) — допустима, пока у кита нет потребителей вне монорепозитория:
  поиск по `apps/` и правка всех вызовов в том же изменении.

## Обновление зависимостей

| Зависимость      | На что смотреть                                                                                                                                              |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `radix-ui`       | `Tour` опирается на `radix-ui/internal` (FocusScope, Presence) — его истории первыми; затем все всплывающие                                                  |
| `storybook`      | классы `sb-unstyled` и селекторы документации (`preview.css`), `NAVIGATE_URL` в `mdx-components.tsx`, remark-плагин заголовков кода в `main.ts`, `storySort` |
| `@fontsource-*`  | подмножества: если появилась псевдографика — сравнить с глифами `Haunt TUI`; кириллица у шрифтов «сигнала»                                                   |
| `shiki`          | список грамматик в `code-block/languages.ts`, JS-движок регулярок (без WASM)                                                                                 |
| `react`          | `ref` как обычный проп (React 19): компоненты принимают его в пропсах, `forwardRef` в ките нет                                                               |
| `vite`, `vitest` | проекты `unit` и `storybook` в `vitest.config.ts`, браузерный провайдер Playwright                                                                           |

Порядок: обновить одну зависимость → `pnpm verify:js` → посмотреть затронутые истории глазами. Не обновлять
пачкой: при падении не понять, кто виноват. Ограничения менеджера пакетов на возраст релизов не обходить.

## Вес и производительность

- **Стартовый CSS** приложения — около 21,6 kB. Растёт, если глобальный импорт попал в `main.tsx` (например,
  `@haunt/ui/signal` — до 69 kB). Смотреть в выводе `pnpm build:web`.
- **Ленивое** — рендер `Markdown`, подсветка `CodeBlock`, `EmojiPicker`, ядра и сцены `fx`, `QrCode`, `Tour`,
  `Toaster`. В модулях, достижимых из `index.ts` статически, тяжёлых импортов нет — только `import()`.
- **`sideEffects`** в `package.json` пакета — только CSS, `styles.ts` и `signal.ts`. Новый модуль с побочным
  эффектом (регистрация, глобальный слушатель) — вход отдельным файлом, а не импорт внутри компонента.
- **Анимации** — только `transform`, `opacity`, `filter`; исключения перечислены в README с причиной у каждого.
- **Кадр** у эффектов `fx` — общий планировщик с бюджетом; эффект, который не укладывается, сползает на
  Canvas 2D или статику (`data-fx-renderer`).

## Посмотреть глазами

Тест не скажет, что компонент выглядит чужим или бледным. Снимки историй в нужном окружении — Playwright
против dev-сервера Storybook; глобалы тулбара передаются в адресе:

```js title="test-results/shot.mjs"
import { chromium } from '@playwright/test';

// Headless Chromium по умолчанию прячет полосы прокрутки — для проверки прокрутки флаг снимаем
const browser = await chromium.launch({ ignoreDefaultArgs: ['--hide-scrollbars'] });
const page = await browser.newPage({
  viewport: { width: 1000, height: 640 },
  deviceScaleFactor: 2,
});

// Глобалы тулбара: тема, TUI, стиль, эффекты, язык — через «;»
await page.goto(
  'http://localhost:6006/iframe.html?id=tui-logview--default&viewMode=story&globals=theme:light;tui:off',
);
await page.waitForTimeout(1000);
await page.screenshot({ path: 'test-results/logview-light-off.png' });
await browser.close();
```

- Папки `test-results/` в `.gitignore`: снимки и скрипты проверок кладите туда.
- Проверяйте **обе темы**, **`tui:off`**, **`style:signal`**, **ширину 390 px** и **масштаб 1x** (тонкие линии и
  глифы выглядят иначе, чем на 2x).
- Список историй с их id — `http://localhost:6006/index.json`.

## Чек-лист изменения кита

- [ ] Цвета, размеры, отступы — токены; вложенные радиусы — формулой.
- [ ] Ни одной строки в разметке; новые ключи — во всех словарях.
- [ ] JSDoc у компонента и пропсов; истории на каждое состояние; `play` у интерактивного.
- [ ] Обе темы, `data-tui="off"`, `data-style="signal"`, reduced-motion, `data-effects="off"`.
- [ ] Клавиатура без мыши: фокус видно, Esc закрывает, фокус возвращается.
- [ ] Узкое окно: ничего не вылезает, длинный текст обрезается или переносится.
- [ ] Нет узнаваемой чужой детали (таблица 10c в `docs/ui-kit.md`).
- [ ] README пакета и, если это решение, `docs/ui-kit.md` обновлены.
- [ ] `pnpm verify:js` зелёный; упавшая история прогнана отдельно и разобрана.
