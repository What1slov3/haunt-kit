# Дизайн-система: техническая база и решения

Как устроен кит `packages/ui/src` и почему так. Правила использования и рецепты («как добавить
примитив, токен, акцент») — в `packages/ui/README.md`; каталог — Storybook; устройство Storybook —
`packages/ui/.storybook/README.md`; фильтр изображений — `packages/ui/src/filtered-image/README.md`. Здесь — то, что
под ними: из чего собрано, как течёт тема и акцент, где граница CSS и JS, и какие решения за этим стоят.

## Картина целиком

```
                  ┌───────────────────────────────── CSS (глобально, порядок важен) ─┐
main.tsx          │ tokens.css     значения: основа, тема, акцент, производные        │
 '@haunt/ui/      │                                                                   │
   styles'        │                                                                   │
 initTheme()  ──► │ global.css     сброс, :focus-visible, reduced-motion              │
 initEffects()    │ animations.css keyframes + переменные --anim-*                    │
 (data-* на html) │ effects.css    data-effects → интенсивности --fx-*; кольца, свет  │
                  └───────────────────────────────────────────────────────────────────┘
                                   ▲ читают переменные
<ThemeProvider>                    │
  тема / эффекты в state ──────────┤   примитив = <name>.tsx + <name>.module.css
  Tooltip.Provider                 │     поведение: Radix   индикаторы: FLIP (WAAPI)
  прожектор (1 слушатель на окно)  │     стиль: CSS Modules + var(--token)
<AccentScope> / <ThemeScope> ──────┘   порталы → usePortalContainer() → хост в <body>
```

Три слоя, каждый со своей ответственностью:

1. **Значения** — CSS-переменные. Цвет, размер, длительность, интенсивность эффекта. Тема, акцент и уровень
   эффектов меняют только значения.
2. **Переключатели** — data-атрибуты: `data-theme`, `data-effects`, `data-tui` на `<html>` или любом
   контейнере. JS ставит атрибут, CSS сам пересчитывает значения ниже по дереву.
3. **Компоненты** — читают переменные и ничего не знают о том, какая сейчас тема или акцент.

Следствие: смена темы или акцента — это одна запись атрибута или трёх переменных, без ре-рендера React и без
JS в каждом компоненте.

## Решения

### 1. CSS Modules + CSS-переменные, а не CSS-in-JS и не Tailwind

- **Почему.** Ноль рантайма: стили — статический CSS, который Vite собирает при сборке. Это важно в Tauri
  (WebView на слабых машинах) и не спорит с React Compiler. Каскад CSS-переменных и есть механизм темизации:
  контейнеру переопределили `--accent`, и всё под ним перекрасилось. В CSS-in-JS для этого понадобился бы
  контекст и ре-рендер, в Tailwind — классы-варианты на каждом элементе.
- **Почему не Tailwind, хотя Fumadocs на нём.** У Fumadocs мы взяли визуальную основу и имена семантики
  (`background`, `card`, `muted`…), а не инструмент. Переменные читаются одинаково из модуля, из глобального
  CSS эффектов и из canvas (`getComputedStyle`), и так нужно для фона и фильтра изображений.
- **Цена.** Токены не типизированы, опечатка в `var(--txt)` молча даёт значение по умолчанию. Keyframes и
  эффекты пришлось вынести в глобальные файлы (см. 6 и 7).

### 2. Семантические токены в два слоя

- Цвета названы **по смыслу, не по оттенку**: `--text-muted`, `--surface-2`, `--state-selected-bg`. Тема
  меняет значения, компоненты остаются как есть.
- **Основа** — имена shadcn/Fumadocs: `--background`, `--foreground`, `--card`, `--popover`, `--muted`,
  `--primary`, `--border`, `--ring`. Их `accent` (серое выделение) у нас называется `--highlight`: имя
  `--accent` занято акцентом пространства.
- **Прежние имена** (`--bg`, `--panel-*`, `--surface-*`, `--text-*`, `--glass`) выражены через основу. Модули
  компонентов при редизайне не менялись: сменились значения под теми же именами.
- **Тонкость каскада, на которой всё держится.** `var()` внутри custom property вычисляется **там, где
  объявлено**, а наследуется уже готовое значение. Отсюда два места в `tokens.css`, которые выглядят странно:
  - псевдонимы (`--bg: var(--background)`) объявлены на `:root, [data-theme]`, а не только на `:root`. Иначе
    `ThemeScope theme="light"` унаследовал бы тёмный `--bg`, вычисленный на корне;
  - производные от акцента (`--accent-soft`, `--accent-text`, тени с каплей акцента) объявлены на `*`. Иначе
    `AccentScope` менял бы `--accent`, но `--accent-soft`, посчитанный на `:root`, остался бы старым. Цена —
    несколько `color-mix` на каждый элемент.
- **Тёмная тема на `:root`.** Она основная, поэтому работает и без атрибута; светлая —
  `[data-theme='light']` на `<html>` или на любом контейнере.

### 3. Тема и акцент — каскадом, со скоупами

- `initTheme()` и `initEffects()` вызываются в `main.tsx` **до первого рендера**: сохранённая светлая тема не
  мигает тёмной. `ThemeProvider` держит то же значение в состоянии только для переключателей в UI.
- **Акцент пространства — три цвета** (`--accent`, `--accent-2`, `--accent-contrast`), остальное
  выводится через `color-mix(in oklab, …)`. Пресеты подобраны под контраст белого текста ≥ 4.5:1 (AA).
  Своё сообщество может прийти со своим цветом, и кит не должен знать список цветов заранее.
- `AccentScope` / `ThemeScope` — контейнеры с другим акцентом или темой. Витрина показывает обе темы рядом,
  экран сообщества красится в его цвет.

### 4. Порталы через хост с `display: contents`

- **Проблема.** Меню, поповеры и диалоги порталятся в `<body>`, чтобы выйти из `overflow`, `transform` и
  `backdrop-filter` родителей. Но в `<body>` они теряют акцент и тему скоупа.
- **Решение.** Скоуп заводит в `<body>` хост-элемент с `display: contents` (не участвует в раскладке и
  стекинге) и копирует на него свои атрибуты и переменные (`usePortalHost`). Примитивы берут контейнер из
  `usePortalContainer()`. Без скоупа это `undefined`, то есть Radix порталит в `<body>`.
- **Итог.** Всплывающее и выходит из обрезки, и красится как скоуп. Вручную `container` нигде не передаётся.

### 5. Поведение — Radix, вид — свой

- Фокус-ловушки, клавиатура, roving focus, `aria-*`, закрытие по Esc и клику снаружи, позиционирование с
  разворотом у края — это то, что дорого написать правильно и легко сломать. Это делает Radix (`radix-ui`,
  один пакет). У нас — только стили и состав частей.
- **Почему не shadcn как есть.** shadcn — это Radix + Tailwind, скопированные в проект. От него взяты
  семантика имён и состав частей (`Dialog = { Root, Trigger, Content… }`), стили написаны в модулях под нашу
  плотность.
- **Составные компоненты** — объект в `<name>.ts`, части — в `<name>-parts.tsx`. Файл с JSX экспортирует
  только компоненты, иначе ломается Fast Refresh (`react-refresh/only-export-components`).
- **Контролы форм** связываются с `<Field>` через контекст (`useFieldControl`): id метки, `aria-describedby`
  и `invalid` приходят сами.

### 6. Движение: CSS для мелочей, FLIP для индикаторов, keyframes только через переменные

- Наведение и нажатие — CSS-переходы 90–150 мс. Появление всплывающего — глобальные keyframes по
  `data-state` Radix. Общие элементы (индикатор вкладок, подсветка активного канала) переезжают через FLIP:
  уходящий индикатор запоминает свой прямоугольник, появившийся проигрывает обратный путь через Web
  Animations API (`lib/use-shared-indicator.ts`). Раньше это был Motion `layoutId` — 135 kB ради двух
  индикаторов в каждом экране; теперь Motion — необязательный вход `@haunt/ui/motion` для экранов, где он
  правда нужен (решение 15).
- **Анимируются только `transform`, `opacity`, `filter`.** Это свойства композитора: не вызывают раскладку
  и перерисовку. Единственное исключение — `@property --beam-angle` у бегущего отблеска: там
  перерисовывается кольцо в 1–2 px.
- **Почему keyframes через `var(--anim-*)`.** CSS Modules переименовывают имя в `animation: haunt-pop-in`
  в локальное (`_haunt-pop-in_hash`), и глобальные keyframes не находятся. Анимация не идёт, `animationend`
  не приходит, Radix Presence ждёт его вечно, и закрытое меню остаётся в DOM. Это была причина бага
  «дропдауны не закрываются». Значение переменной модули не переписывают, поэтому `animation:
var(--anim-pop-in)` работает.
- **`prefers-reduced-motion`** гасится в трёх местах: глобальным правилом в `global.css`, в эффектах
  (`--fx-*` → 0), в FLIP-индикаторе и в Motion (`MotionProvider`, `reducedMotion="user"`). Исключение —
  `data-motion-keep` у спиннера и каретки:
  без движения у них пропадает смысл.

### 7. Эффекты как уровень, а не как фичи

- `data-effects="off | subtle | rich"` переводится в **числа**: `--fx-spotlight`, `--fx-glow`, `--fx-beam`,
  `--fx-blur`… и `--fx-play` (`animation-play-state`). Компонент не спрашивает «включены ли эффекты», он
  умножает на интенсивность: `opacity: var(--fx-beam)`. Уровень можно поставить на любой контейнер.
- `effects.css` — глобальный файл с селекторами по **data-атрибутам** (`[data-spotlight]`, `[data-beam]`,
  `[data-edge]`, `[data-grain]`): примитивы в модулях включают эффект атрибутом, и одна реализация служит
  всем.
- **Одна подписка на всё окно.** Прожектор (`spotlight.ts`) вешает один `pointermove` и в
  `requestAnimationFrame` пишет `--spot-x/--spot-y` всем `[data-spotlight]` под курсором (элемент и его
  предки с атрибутом). Панелей много, курсор
  один, поэтому слушатель на каждую панель не нужен.
- **Кольца и кромки** рисует `::before` с маской «полный слой XOR content-box». Остаётся обод шириной
  `--edge-width`, вынесенный наружу на `--edge-offset`. Градиент и вращение живут внутри обода, поэтому
  форма элемента не меняется.

### 8. Геометрия не зависит от фона: вырезы — маской, а не цветом подложки

- **Было.** Точку статуса «вырезали» из аватара обводкой `box-shadow` цвета подложки (`--avatar-ring`).
  Это работает, только пока подложка однотонная и её цвет известен. На панели другого уровня, на плитке,
  на стекле или градиенте получалось тёмное кольцо, заметно темнее фона.
- **Стало.** У аватара со статусом отверстие вырезано маской `radial-gradient` прямо в изображении, и вырез
  прозрачен на любом фоне. Кольцо «говорит» получает то же отверстие третьим слоем маски
  (`mask-composite: intersect, exclude`), поэтому точка не налезает на бегущий отблеск.
- **Правило.** Если элемент должен «выглядеть вырезанным», это маска. Обводка цветом фона — только когда фон
  гарантированно однотонный (бейдж-счётчик в рейле, там это по-прежнему `--avatar-ring`).

### 9. Концентрические скругления

- **Внутренний радиус = внешний − отступ − рамка.** Иначе зазор между слоями в углу толще, чем на сторонах:
  глаз читает это как кривизну, даже если разница 1 px.
- Где радиус выводится из соседнего, он записан формулой, а не подобранным токеном:
  `calc(var(--radius-lg) - var(--space-1) - 1px)` у пунктов меню и select,
  `calc(var(--radius-md) - 3px)` у сегментов. Тогда смена токена не ломает пары.
- **Кольцо, вынесенное наружу, растёт на тот же вынос:** `calc(var(--avatar-radius) + var(--edge-offset))`.
- **Контейнер, который сам обрезает содержимое,** снимает у него скругление: плитка рейла обнуляет
  `--avatar-radius` у аватара сообщества и режет углы своим `overflow: hidden`. Иначе при смене радиуса
  на наведении в углах проступает подложка.
- **Рамка поверх содержимого** — `inset box-shadow` на `::after`, а не `border`. `border` отодвигает
  содержимое внутрь и обводит его полосой подложки (тёмный ободок вокруг цветной плитки).

### 10. Плотность: пары «высота — кегль»

- Контролы — 24 / 28 / 32 px (`--control-sm/md/lg`), строки списков — 28 / 32. Шаг отступов — 4 с полушагами
  2 и 6 для плотных строк. Текст интерфейса 13 px, сообщения 14.
- **Контролы одной высоты — один кегль:** sm 24 / 12, md 28 / 13, lg 32 / 14. Это касается кнопки, поля,
  select, группы переключателей и segment-вкладок. Только так они ровно стоят в одном ряду тулбара.
- **Одна рамка у всех полей** (`field-frame.module.css`): `Input`, `Textarea`, `Select.Trigger` и композер
  берут фон, границу, фокус и ошибку из одних токенов. Своих рамок у полей нет.
- **Состояния интерактивного — общие токены `--state-*`.** Наведение, нажатие и выбранное у строки, кнопки,
  чипа, пункта меню выглядят одинаково, потому что читают одно и то же.
- **Ритм поля: 6 внутри, 16 между.** Метка, контрол и подсказка — через 6 px, соседние поля — через 16.
  Промежуток внутри вдвое меньше промежутка снаружи, и поле читается одним блоком (закон близости).

### 10a. Кнопка: асимметричное нажатие, свет вместо обводки

- **Нажатие и отпускание — разной длины.** Вдавливается за 40 мс, возвращается за 240 мс по кривой без
  перелёта. Симметричная анимация в обе стороны воспринимается как «анимация на кнопке»; асимметричная — как
  физическая кнопка под пальцем. Делается одним `transition-duration` в `:active`, без JS.
- **Свет — прожектор внутри кнопки,** тот же механизм, что у панелей (решение 7), с `--spot-size` и
  `--spot-gain` под маленький элемент. Градиентная обводка у основной кнопки убрана: кольцо в 1 px снаружи
  светлой плашки читалось как ошибка вёрстки, а не как акцент.
- **Прожектор светит по цепочке.** Раньше подсвечивался только ближайший `[data-spotlight]`, и панель гасла,
  когда курсор заходил на кнопку внутри неё. Теперь `spotlight.ts` обновляет всех предков с атрибутом.
- **Подтверждение удержанием** (`holdToConfirm`) — для необратимого вместо диалога «вы уверены?». Заливка
  идёт линейно за время удержания (`--hold-duration`), с `data-motion-keep`: при reduced-motion прогресс всё
  равно виден, это обратная связь, а не украшение. Клавиатура — удержание Space / Enter, автоповтор
  игнорируется.
- **Дополнения кнопки — данные, а не разметка:** `arrow`, `shortcut` (Kbd цвета текста кнопки, а не серая
  плашка), `count`. Экран не собирает их руками, и они одинаковы во всём приложении.

### 10b. TUI — словарь на токенах

- У каждого знака одно значение: `>` — раздел, `[ ]` — метка, `//` — пояснение, `!` — ошибка, `│` —
  разделитель. Знак — значение custom property (`content: var(--tui-hint)`), поэтому `data-tui="off"` на
  контейнере убирает знаки, не трогая разметку и компоненты.
- `--font-tui` — шрифт служебных подписей (метки полей): моно в TUI, гротеск без него. Моно у `Kbd`,
  времени и счётчиков от TUI не зависит: это иерархия, а не декор.
- Компоненты раздела TUI — терминал по правилам, а не вёрстка «под него»: настоящие знаки псевдографики из
  своего шрифта глифов, сетка `ch` × `--tui-leading`, фокус курсором и инверсией вместо колец и скруглений.
  Первая версия рисовала рамки CSS-линиями, прогресс — системным шрифтом и держала веб-поля, плашки и стекло:
  выглядело как вёрстка в моно-шрифте. Знаки — текстом, потому что так их можно скопировать, а `├── src` в
  выводе бота стыкуется так же, как рамка компонента.

### 10c. Лента и профиль — свой облик, а не Discord

Первая версия `ProfileCard` и `MessageItem` повторяла узнаваемые детали Discord почти дословно. Заменены именно
они — то, по чему макет узнают с одного взгляда:

| Было (Discord)                                         | Стало (Haunt)                                                                                   |
| ------------------------------------------------------ | ----------------------------------------------------------------------------------------------- |
| баннер и круглый аватар внахлёст, вырез под статус     | аура цвета профиля из угла карточки, аватар — скруглённый квадрат в строке с именем             |
| точка статуса на аватаре                               | статус словом в моно-строке под ником (`● в сети`, у «отошёл» и «не беспокоить» — своя форма)   |
| капсом «О СЕБЕ», «РОЛИ»; роли пилюлями с точкой        | `// о себе` — комментарий TUI; роли — метки `[ Основатель ]` цветом роли, как бейджи в ленте    |
| время сразу после ника, у продолжения — слева          | время моно у правого края первой строки                                                         |
| панель действий, всплывающая над сообщением            | кнопки в той же строке, рядом со временем                                                       |
| ответ — изогнутая линия от аватара и мини-аватар       | строка-след `↳ Имя · текст`                                                                     |
| красная линия «НОВЫЕ» с пилюлей справа                 | метка `[ 2 новых ]` акцентом слева, линия гаснет к краю                                         |
| дата посередине между линиями                          | дата у левого края, как подпись раздела                                                         |
| колонки встык через линию (рейл, каналы, лента, люди)  | острова: панели отдельными блоками с зазором, где виден живой фон; рейл лежит прямо на фоне     |
| белая пилюля слева у рейла, плитка меняет скругление   | аура акцента вокруг открытого пространства, точка непрочитанного в углу плитки, форма постоянна |
| «КАНАЛЫ» и `#канал`, «В СЕТИ — 4» (в истории оболочки) | потоки, сцены и лор пространства; путь `Haunt / общий`; «в сцене» и «здесь»                     |

Своё, чего у Discord нет: **след автора** — линия его цвета от аватара вниз вдоль продолжений группы,
сообщения человека читаются одной нитью. Новый компонент ленты или профиля сверяется с этой таблицей: если
деталь узнаётся как чужая — ищем свою в словаре TUI и в примитивах Haunt, а не перекрашиваем чужую.

### 11. Canvas там, где DOM дорог

- **Точечный фон** (`ambient-background/dot-field.ts`). Сетка рисуется один раз во внеэкранный canvas, каждый
  кадр перерисовываются только точки у курсора, волны и до 36 частиц. На скрытой вкладке кадров нет, при
  reduced-motion сетка статична. Тысячи DOM-точек с transition такого не выдержали бы.
- **Шина `ambient`** развязывает фон и остальное: кнопка «отправить» шлёт `ambient.pulseFrom(el)`, фон
  подписан. Компонент не знает про canvas, и его можно вызывать из сервиса.
- **`FilteredImage`**: pixel, Bayer-дизеринг, ASCII. Кадр считается на canvas и кэшируется. Перерисовка
  только при смене размера, темы, акцента или режима, а не на каждый кадр. Палитра читается из токенов
  (`--image-dither-*`), поэтому фильтр перекрашивается с акцентом. Алгоритмы — в
  `filtered-image/README.md`. GIF и видео декодируются покадрово (`ImageDecoder` / `<video>`), кадр идёт
  через тот же конвейер.
- **Рантайм `@haunt/ui/fx`** — общий для всех эффектов:
  - один rAF-планировщик с бюджетом кадра: эффекты не заводят свои циклы, на скрытой вкладке и вне экрана
    кадров нет;
  - стратегии `webgl → canvas2d → static`: эффект объявляет, что умеет, рантайм выбирает лучшее доступное и
    пишет выбор в `data-fx-renderer` (видно в DevTools и в тестах);
  - **один общий WebGL2-контекст** на страницу (`fx/webgl/shared-context.ts`): браузер даёт странице около
    16, и десяток фонов исчерпал бы лимит. Потеря контекста переводит эффекты на canvas2d без перезагрузки;
    программный растеризатор (SwiftShader) распознаётся отдельно — он медленнее CPU-ядер;
  - `isMotionAllowed()` — один ответ на «можно ли двигаться» (`data-effects`, reduced-motion) для JS-эффектов;
    CSS-эффекты читают те же условия селекторами;
  - ядра и шейдеры грузятся `import()` при первом монтировании: сразу нужен только планировщик.

### 12. Шрифты локально

Inter и JetBrains Mono — variable-шрифты из `@fontsource-variable/*`, лежат в сборке. Tauri должен работать
офлайн, а один variable-файл заменяет набор начертаний. Моно — для метаданных, времени, `Kbd`, счётчиков:
это TUI-акцент, а не основной текст.

Псевдографики, блоков, брайля и знаков Powerline в подмножествах fontsource нет — их рисует свой шрифт
`Haunt TUI` (7 КБ, `theme/fonts/haunt-tui.woff`): глифы строит геометрией `scripts/tui-font.ts` ровно в клетку
JetBrains Mono (600 × 1320 единиц). Внешний шрифт с этими знаками (Iosevka, Nerd Font) весит мегабайты и
приносит свою ширину клетки; свой — только нужные знаки и та же сетка.

### 13. Публичный API и границы

- Импорт только из `@haunt/ui` (`index.ts`). Внутренности (`menu/`, `lib/`, `theme/*`) снаружи не видны.
- Пропсы расширяют `ComponentPropsWithRef<'tag'>`: `ref`, `aria-*` и обработчики проходят насквозь, и
  обёрточных пропсов вроде `onClickButton` нет.
- Варианты — `cx(styles.root, styles[variant])`, состояния — data-атрибуты (`data-active`, `data-unread`),
  на которые смотрят и CSS, и тесты. Состояние Radix-переключателя — по `aria-pressed` / `aria-checked`, а не
  по `data-state`: обёртка `Tooltip` перезаписывает `data-state` своим.

### 13a. Композиции в ките

- Палитра команд, выбор даты, плитка участника голоса — уже не примитивы, но в `@haunt/ui` им место, пока в
  них нет бизнес-смысла: палитра знает про группы, ранжирование и клавиши, но не про каналы.
- **Данные массивом, когда логике нужно всё сразу.** `CommandPalette` принимает `items`, а не детей
  `.Group` / `.Item`: ранжированию нужны все команды одновременно, подсветке — подпись строкой, «недавним» —
  id. Декларативные дети потребовали бы регистрации эффектами (как в cmdk) с лишним рендером.
- **Логика — чистыми функциями рядом, с тестами:** ранжирование палитры и `Combobox`, математика дат,
  сортировка таблицы, контраст цвета, геометрия кольца, относительное время. Компонент — тонкий слой.
- **Даты — `IsoDate` строкой** (`YYYY-MM-DD`), арифметика в UTC: `Date` в стор не кладётся (plain data), а
  календарный день не зависит от часового пояса.
- **Один таймер на все экземпляры** (`Timestamp`): сотня сообщений не заводит сотню интервалов, подписи
  обновляются одним рендером.
- **Слой без триггера возвращает фокус сам** (`lib/use-return-focus.ts`): палитра по сочетанию и диалог из
  меню иначе роняли фокус на `<body>`.
- **Клавиши — `lib/hotkey.ts` + `useHotkey`**: буквы сравниваются по `event.code`, чтобы Ctrl+K работал в
  русской раскладке; `mod` — Ctrl или ⌘; в поле ввода сочетание не перехватывается без явного разрешения.

### 14. Проверка

- **Каждая история Storybook — тест** (`@storybook/addon-vitest`, Chromium через Playwright): рендер плюс
  play-функция. Меню открываются и закрываются, фокус возвращается, вкладки переключаются. Входит в
  `pnpm test`.
- **e2e против витрины `/ui`** (`apps/web/e2e`): тема, акцент, эффекты, TUI, прожектор, мессенджер, фильтр.
  Запускается руками после правок примитивов.
- **Аудиты вёрстки** — разовые скрипты Playwright, которые обходят все истории и витрину и ищут:
  - неконцентричные скругления (вложенный слой и кольца `::before`);
  - фокус-кольцо вокруг невидимой обёртки;
  - обрезанный без многоточия текст и вылезание за родителя;
  - иконки не по центру и контролы разной высоты в одном ряду.

  Лежат в `apps/web/test-results/audit/` (в .gitignore). Если понадобятся постоянно, стоит перенести
  проверки скруглений и высот в `e2e/`.

### 15. Отдельный пакет `@haunt/ui` и вес сборки

- **Пакет из исходников** (`packages/ui`, как `@haunt/state`): `exports` указывает на `src`, приложение
  собирает его своим Vite — HMR и никакого шага сборки. Storybook и тесты историй живут в пакете: кит
  проверяется сам по себе, без приложения. Собранный `dist` — когда появится потребитель вне монорепозитория.
- **Три входа:** `@haunt/ui` (код), `@haunt/ui/styles` (шрифты и глобальный CSS — один раз в `main.tsx`),
  `@haunt/ui/motion` (пресеты и провайдер Motion).
- **`sideEffects`: только CSS и `styles.ts`.** Без этой пометки Rollup считал импорт CSS-модуля побочным
  эффектом и оставлял в сборке CSS всех компонентов, даже неиспользуемых: стартовый CSS был 96 kB, стал 22 kB.
  Отсюда же правило: побочные эффекты (импорт шрифтов, глобального CSS) — только во входе `styles`.
- **Разбиение по маршрутам.** Индекс страницы — точка разбиения: отдаёт `lazy()`-обёртку, а не модуль, так
  что приложение импортирует страницу из её публичного API и всё равно получает отдельный чанк. Подготовка
  демо (`bootstrapStateDemo`) — тоже через `import()`.
- **Тяжёлое внутри кита — лениво:** вьюпорт `Toaster` (Radix Toast, ~30 kB) подгружается при первом
  уведомлении; подсветка `CodeBlock` — shiki «по деталям» (ядро + JS-движок регулярок, без WASM, ~170 kB) и
  отдельный чанк на каждую грамматику, при первом блоке кода. Тема shiki — на CSS-переменных из токенов кита,
  второй темы для светлой не нужно. Значения из shiki (enum `FontStyle`) в коде, который грузится сразу, не
  импортируются — вместо них числа: импорт значения притянул бы пакет в стартовый чанк, `import type` — нет. React — отдельный vendor-чанк: меняется реже кода и живёт в кэше браузера между релизами.

| Сборка                | Стартовый JS (gzip)                | Стартовый CSS (gzip) |
| --------------------- | ---------------------------------- | -------------------- |
| до (2026-10-26, утро) | 748 kB (242 kB), один чанк         | 96 kB (20 kB)        |
| после                 | 287 kB (92 kB): React 222 + код 65 | 22 kB (7 kB)         |
| 1.0 (2026-10-27)      | 287 kB (93 kB): React 222 + код 65 | 24 kB (8 kB)         |

Витрина (`/ui`) — свой чанк 289 kB: в нём Motion и почти весь кит; демо состояния — 56 kB + общий 45 kB.

Входов стало шесть: к трём добавились `@haunt/ui/signal` (стиль «сигнал», 17), `@haunt/ui/fx` (эффекты, 11) и
`@haunt/ui/sound` (звуки интерфейса). `signal.ts` тоже в `sideEffects`, и импортировать его надо там, где стиль
включается, а не в `main.tsx`: глобальный импорт поднимал стартовый CSS с 22 до 69 kB (шрифты и палитра).

### 16. Строки — словарь по компонентам

- Ни одной видимой или озвучиваемой строки в коде компонента: подписи, `aria-label`, плюрали — из словаря
  `UiStrings` (`strings/ui-strings-types.ts`), сгруппированного по компонентам. Словарь — один интерфейс,
  поэтому забытый перевод — ошибка `tsc`, а не пустая подпись.
- `UiStringsProvider` принимает локаль (`ru` по умолчанию, `en`) и частичные переопределения: приложение
  меняет формулировку, не форкая компонент. Компонент читает `useUiStrings()`, даты и числа — `useUiLocale()`
  с `Intl`; множественное число — `plural()` на `Intl.PluralRules`, а не `n === 1`.
- Тест-сторож `strings/no-hardcoded-strings.test.ts` разбирает исходники TypeScript-парсером и ищет кириллицу
  в литералах и JSX-тексте: правило держится проверкой, а не памятью. Данные (эмодзи-словарь) — явные
  исключения с причиной.
- Пропсы-подписи (`label`, `placeholder`) остаются: словарь — значение по умолчанию, а не запрет.

### 17. Стиль «сигнал» — дополнение, а не тема

- Включается `data-style="signal"` на любом предке (весь экран или один блок) и живёт в `@scope`: палитра,
  шрифт заголовков (`data-signal-font`), акцент (`data-signal-accent`), срезанные углы и метки действуют только
  внутри и не протекают за границу блока.
- Компоненты не знают про стиль: у них есть **ручки** — токены с запасным значением базового стиля
  (`var(--knob, <как было>)`). Без `data-style` ручки не заданы и всё выглядит как раньше — проверено
  попиксельным сравнением историй в обеих темах. Новая ручка — только с запасным значением.
- Шрифты — десять на выбор в витрине (четыре с кириллицей), грузятся только со входом `signal`. Выбор
  владельца закрепит один, остальные уйдут из зависимостей.

### 18. Раскладка от контейнера, а не от окна

- В `AppShell` ширину содержимого меняют панели, окно об этом не знает — точки перелома по `@media` врали бы.
  Поэтому раскладка кита решает по ширине своего места: `WithSidebar` и `Switcher` — приёмы Every Layout на
  `flex-wrap` (боковая часть уходит вниз, когда основной не хватает `contentMin`; ряд целиком становится
  столбцом уже `threshold`), `ChatLayout` — container query на себе, `Masonry` — колонки по ширине контейнера.
- **Лейаутов три, а не по одному на вид страницы:** `PageLayout` (ширина колонки + шапка + боковая колонка)
  закрывает ленту, документ и обзор; `ChatLayout` и `SettingsLayout` устроены иначе по сути — лента на всю
  высоту с прижатым композером, разделы с полосой несохранённого.
- **`Masonry` — свой расчёт, а не CSS columns:** в колонках порядок идёт сверху вниз, и чтение с экрана
  расходится с тем, что видно. Расчёт — чистая функция (самая короткая колонка), плитки — абсолютными позициями,
  без JavaScript — обычная сетка. CSS `masonry` пока только за флагом в Firefox.
- **`Sticky` сообщает, что прилип:** CSS этого не умеет, поэтому — `IntersectionObserver` с границей корня,
  сдвинутой на отступ + 1 px; состояние — `data-stuck` без перерисовки React.

### 19. Составные значения — тоже токены

- Одинаковые составные значения, повторённые по модулям, — токен: `--glass-filter` (фильтр стекла — был
  вписан в 24 модуля), `--segment-inset` / `--segment-raise` (колодец и плашка сегмента — ToggleGroup,
  Tabs, клавиатура генератора). Они в блоке `*`, а не в `:root`: так `--blur-glass` или `--border`,
  заданные на контейнере (`setTokens`), доходят и до составного значения.

## Известные долги

- В интерфейсе самого Storybook (менеджере) системный шрифт: Inter туда не подключён.
- `FilteredImage` не пересчитывает кадр, если сменился только `devicePixelRatio` (окно перенесли на монитор с
  другим масштабом).
- Анимированный GIF в Safari / WKWebView (Tauri на macOS) фильтруется первым кадром: там нет
  `ImageDecoder`. Видео анимируется везде.
- Шрифт стиля «сигнал» не выбран: в зависимостях десять, нужен один (см. 17).
- Английский словарь не вычитан носителем языка — список строк для проверки в
  `research/ui-kit-work/final-pass-notes.md`.
- Кит, кроме витрины, ещё не применён ни одним настоящим экраном: API может поменяться при первом
  использовании. Заморозка это допускает (решения 0013 и 0014) — правка API по требованию экрана, а не впрок.
- `Tooltip.Provider` в `ThemeProvider` держит в стартовом чанке Radix Tooltip с floating-ui (≈30 kB по карте
  сборки) даже на экране без подсказок. Убрать — значит потерять общую задержку между подсказками (переход
  с одной на другую без ожидания); на реальных экранах подсказки есть почти везде, поэтому пока оставлено.
- Имена токенов в CSS-модулях не проверяются: из кода есть типизированное API (`tokens`, `tokenVar`,
  `setTokens`), а опечатка в `var(--…)` в CSS видна только глазами. Если начнёт стоить времени — stylelint с
  правилом на неизвестные custom properties по `tokens.generated.ts`.
- `ChatLayout` на узком месте кладёт панель треда поверх ленты, но не ловит фокус и не закрывается по Esc:
  это делает экран (кнопка закрытия в панели). Если у трёх экранов это повторится — в лейаут.
- Лейауты и шапки не применены ни одним настоящим экраном — первое применение может поменять их API (1.x).
